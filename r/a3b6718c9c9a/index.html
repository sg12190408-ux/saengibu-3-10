겸아, 창의적 사고(90)가 정점이야 — 주름관 전원연장선 발명, 레이저 사격장 광센서를 웹캠 인식 시스템으로 갈아엎은 것, 죄수의 딜레마 기계 직접 구현, 루빅큐브 큐브이미지 분류 AI 모델 라벨링까지. '있는 걸 그대로 쓰지 않고 다시 설계한다'는 흔적이 한 학생 기록에서 네 번 보일 정도면 진짜 무기야. 자기관리(88)도 강해 — 1·2학년 개근, 1년간 출석부 도우미 단 하루도 빠짐없이 수행, 매일 쉬는시간 과학책 3쪽 습관까지 행특에 박혀 있어. 한 가지만 — 의사소통(74)은 '조용·내향'이라는 행특 코멘트 때문에 점수가 살짝 낮은데, 이건 약점이 아니라 너의 '깊게 파고드는' 스타일과 짝이야. 면접에서 '저는 말로 설명하기 전에 만들어 보여줍니다'로 자연스럽게 전환 가능.

SECTION 05

너의 베스트 모먼트 3

생기부에서 가장 잘 쓰인 문장 3개. 왜 좋은지를 우수 세특 패턴 분류로 풀어줄게.

🟢 동아리 STEAM2 · 2학년 패턴 ① 동기·과정·결과 + ⑥ 머리·가슴·발 통합

레이저 사격장 — 광센서를 웹캠 이미지 인식으로 개조

"선배들이 만든 레이저 사격장을 개선하고자 사격 과정의 코드를 다시 짜고, 광센서 기반 과녁을 웹캠 기반 레이저 인식 시스템으로 개선하여 단순 명중 여부뿐만 아니라 착탄 위치에 따른 배점 및 합산 시스템으로 바꿈. 처음 다루어보는 코딩 프로그램도 적극적으로 배우고 끝까지 멘토에게 질문. 주변 광원 방해·가상 과녁 크기 오차 등 개발 과정의 문제를 계속 해결."

✨ '있는 걸 그냥 쓴 게 아니라 시스템 자체를 갈아엎었다'는 단 한 줄이 이 학생을 평범한 동아리원에서 엔지니어 후보로 끌어올려. 공학 학종 평가자가 가장 좋아하는 '리엔지니어링' 사례.
🟢 진로활동 과학심화실험 · 2학년 패턴 ① + ⑤ 반성적 실마리형

간이 발전기 — 데이터 오차를 직접 추적해서 잡음

"전자기 유도·렌츠 법칙으로 자석이 코일에 낙하할 때의 유도 전류·자기장 제동을 관찰. 실험 과정에서 발생하는 데이터 오차의 원인을 추적하며 주변 자성 물체를 제거하고 코일 높이와 완충재를 조정하여 신뢰성을 높임. 네오디뮴 자석·에나멜선으로 간이 발전기를 제작해 역학에너지 → 전기에너지 변환으로 LED 점등."

✨ '오차의 원인을 추적해서 환경을 직접 바꿨다'가 핵심. 결과보고가 아니라 과정에서 본인이 한 일이 보여 — 실험 동력학을 아는 학생이라는 인상.
🟢 인공지능 기초 · 2학년 패턴 ② 키워드 연계형 + ① 동기·과정·결과

루빅큐브 풀이 기법 분류 AI — 데이터 라벨링까지 직접

"6면 큐브 이미지가 주어졌을 때 두 개의 대표 풀이 기법 중 어느 것이 효과적일지 분류하는 모델을 계획. 본인이 웹상의 큐브 조합을 직접 두 기법으로 풀어보고 효과적인 기법을 라벨링한 점이 돋보임. 성능평가에서 분류가 완벽하지 않다는 점을 확인하고, 더 많은 데이터 수집의 필요성·접근 방향·주의 사항을 정리."

✨ '데이터를 본인이 직접 만들었다(라벨링)'는 한 줄이 이 활동을 진짜 머신러닝 프로젝트로 만들어. 단순 사용자가 아니라 데이터를 설계하는 사람. AI×공학의 핵심 자산.

도체·절연체 회로 수행평가 문항을 본인이 직접 출제 — 두 종류 고체 + 두 스위치 회로의 조건별 분석을 유도. "두 고체 물질의 정체를 미리 고정하지 않고 선택지에서 가정하도록 구성"하며 사고의 유연성을 점검하려는 의도가 분명히 드러남. 에너지띠·반도체 전하 운반자까지 인포그래픽으로 정리하고, 뇌파·심전도 응용까지 확장.

양호 · 광학 응용 직결

⚙️ 1. 레이저 사격장 v2 — 광센서 vs 이미지인식 정량 비교

난이도 ★★☆ 3주 키워드 연결: 메이커·이미지인식·코딩
💚 왜 겸이에게? 2학년 STEAM2에서 광센서를 웹캠 인식으로 갈아엎은 흐름의 정량 후속편. '바꾸긴 했는데 얼마나 좋아졌는지'를 숫자로 보여주는 한 단계가 빠져 있어. 같은 활동을 1→2→3학년 수직으로 연결하면 학종 패턴 ②(키워드 연계) 완성. 면접에서 "왜 너인가?"에 "같은 시스템을 두 방식으로 만들어 본 학생"으로 답할 수 있는 한 장이 손에 남아.

📚 알아두면 좋은 핵심 이론

  • 광센서(Photoresistor·CdS): 빛의 세기에 따라 저항값이 변하는 소자. 단순·저렴하지만 외부 조명에 민감하고 위치 정보를 못 줘.
  • 이미지 인식(Image Recognition): 카메라 픽셀에서 색·밝기·형태 패턴을 추출해 위치까지 판별. OpenCV의 임계값 이진화(thresholding)가 가장 기본.
  • True Positive Rate / False Positive Rate: 진짜 적중을 맞춘 비율 vs 헛것을 적중으로 잘못 본 비율. 검출 시스템 성능을 말할 때 항상 짝으로 쓰여.
  • 지연시간(Latency): 입력 → 결과 표시까지 걸리는 시간. 게임·로봇 제어에서 30ms 이상이면 사람이 느낄 만큼 느려져.
  • 마이크로컨트롤러 ADC: Arduino가 아날로그 광센서 값을 0~1023 디지털로 바꾸는 기능. 샘플링 속도가 곧 검출 속도의 한계.

A. 실험형 / 실천형

  • 광센서 회로 vs 웹캠 OpenCV 시스템 — 동일 표적·동일 거리에서 30회 반복 측정
  • 적중 검출률·오검출률·지연시간(ms)을 표로 비교
  • 외부 광원(형광등·태양광·암실) 3조건에서 검출률 변화 그래프
  • '개선 전 vs 후' 비교표 1쪽 + 시연 영상 30초 산출

B. 문헌형

  • DBpia·RISS 컴퓨터 비전 표적 검출, OpenCV image thresholding
  • 대한전자공학회·한국로봇학회 학회지의 비전 인식 시스템 사례
  • 한국과학창의재단 메이커 교육 자료, KOSIS 메이커 통계
  • 단행본: '러닝 OpenCV' 1·2장 또는 '바닥부터 배우는 컴퓨터 비전'

🚀 어떻게 시작하면 될까

  1. 두 시스템 회로·코드 다시 세팅하기⏱ 1~2h
    광센서 측: Arduino UNO + CdS + 10kΩ 저항으로 분압 회로. analogRead(A0)로 빛 변화 측정. Tinkercad(tinkercad.com)에서 회로 시뮬레이션 먼저 검증하면 안전. 웹캠 측: 2학년 본인 코드 그대로 + import cv2; cap = cv2.VideoCapture(0). 두 코드의 검출 함수 위·아래에 time.time() 또는 millis()를 박아 시간 기록 준비.✓ 완성품: 두 시스템이 같은 표적에 동시 작동하는 사진 1장 + 검색 키워드 메모 5개.
  2. 적중 검출률·오검출률 30회 측정 표 만들기⏱ 2~3h
    실험 설계: 거리 1m·표적 5cm 원 → 같은 위치에 30번 발사. 변수표 회차 / 광센서 검출(O·X) / 웹캠 검출(O·X) / 외부 광원 강도. 빈 칸에 헛것을 잡은 횟수도 따로 카운트(False Positive). 형 누나에게 1회 발사 도와달라 부탁하면 30회가 30분 안에 끝나. 결과는 Google Sheets로 입력하면서 바로 합계 함수 =COUNTIF로 비율 계산.✓ 완성품: 30행 측정 시트 .xlsx 1개 + TPR·FPR 4개 숫자.
  3. 지연시간(ms) OpenCV 프레임 카운트로 정량화⏱ 1~2h
    웹캠 코드에 start = time.time() → 검출 직후 print((time.time()-start)*1000, 'ms'). 광센서 측은 millis() 차이로 동일하게. 30회 평균 지연·표준편차를 비교. 외부 광원 3조건(형광등 ON·태양광·암실)에서 각 10회 측정 → matplotlib로 막대 그래프 1장. 핵심 한 줄: "검출률은 웹캠이 우수, 지연은 광센서가 우수" 같은 trade-off가 보일 거야.✓ 완성품: 지연시간 비교 막대 그래프 .png 1장 + 조건별 데이터 표.
  4. '개선 전 vs 후' 비교표 + 시연 영상 30초 산출물 만들기⏱ 2h
    A4 1쪽 비교표 — 지표 / 광센서 / 웹캠 / 차이. 마지막에 "어떤 상황에 어느 방식이 유리한가" 본인 언어 한 단락(외부 광원·지연 허용치·예산 기준). 시연 영상은 스마트폰 30초 — 같은 표적, 두 시스템이 동시 반응하는 모습. 마지막에 대한전자공학회 또는 한국로봇학회 학회지에서 비전 인식 정확도 보고 1편 인용 한 줄 추가하면 깊이 ↑. 메카트로닉스 동아리·STEAM 부스에서 발표 자료로 직결.✓ 완성품: A4 비교표 1매 + 시연 영상 30초 + 보고서 4쪽.

🔌 2. 간이 발전기 — 코일·자석 변수의 발전 효율 정량 분석

난이도 ★★☆ 2~3주 키워드 연결: 자석 코일 EMF·물리응용
💚 왜 겸이에게? 2학년 진로활동에서 만든 간이 발전기를 '오차 추적'까지 했지만, 변수별 효율 곡선을 그려본 적은 없어. 물리학Ⅰ에서 배운 패러데이 법칙을 직접 연결하는 한 단계가 비어 있고, 이걸 채우면 '머리(이론) 비중'이 늘어나서 너의 약한 축이 보강돼. "만든 물건 옆에 ε=-N·dΦ/dt를 붙이는 엔지니어"로 한 단계 올라가는 활동이야.

📚 알아두면 좋은 핵심 이론

  • 패러데이 법칙(Faraday's Law): 유도 기전력 ε=-N·dΦ/dt. 코일 감은 횟수(N)와 자속의 시간 변화율(dΦ/dt)이 클수록 전압이 커진다는 가장 기본 식.
  • 렌츠 법칙(Lenz's Law): 유도 전류는 자속 변화를 방해하는 방향. 자석이 코일에 떨어질 때 느려지는 '자기 제동'의 원인이야.
  • 회로의 KVL/KCL: 키르히호프 전압·전류 법칙. 코일 저항·LED 순방향 전압을 함께 고려해야 실제 LED가 켜지는 조건이 계산돼.
  • 자기 누설(Magnetic Leakage): 자속이 코일을 다 지나가지 못하고 새는 양. 이론값과 실측치 차이의 가장 큰 원인 중 하나.
  • 네오디뮴 자석 등급(N35·N42·N52): 숫자가 클수록 잔류 자속밀도가 커. N52는 N35 대비 약 1.4배 강한 자석이야.

A. 실험형 / 실천형

  • 코일 권선수(50·100·200·400턴) × 자석 강도(N35·N42·N52) × 낙하 높이(10·20·30cm)
  • 각 조건 LED 밝기 또는 멀티미터로 V_max 측정 (10회 평균)
  • 이론값 ε=-N·dΦ/dt와 실측치 비교, 오차를 자기 누설·코일 저항으로 분리
  • 3축 그래프로 정리한 1쪽 보고서 + 1쪽 인포그래픽

B. 문헌형

  • DBpia·RISS 전자기 유도 발전기 설계, small-scale generator efficiency
  • 한국전기학회지·한국태양에너지학회지의 소형 발전기 사례
  • KCI(kci.go.kr) 학술논문에서 '코일 권선수 효율' 검색
  • 단행본: '일반물리학' 패러데이 단원, 한국에너지기술연구원 자료

🚀 어떻게 시작하면 될까

  1. 2학년 발전기 다시 꺼내고 측정 장비 준비⏱ 1h
    네오디뮴 자석 3종(N35·N42·N52, 같은 크기 12mm)·에나멜선(0.4mm)·PVC 파이프·디지털 멀티미터(0.01V 분해능). 멀티미터가 V_max를 잡기 어려우면 Arduino + analogRead로 100Hz 샘플링하는 코드를 추가. 검색 키워드 유도 기전력 측정 회로로 회로도 1개 다운로드 후 Tinkercad에서 검증. KVL로 ε = I·(R_coil + R_LED)가 성립하는지 한 번 손으로 풀어보기.✓ 완성품: 측정 회로 사진 1장 + V_max 단발 측정 1번 성공.
  2. 코일 권선수 4종 직접 감기 + 저항값 기록⏱ 2~3h
    같은 PVC 파이프에 50·100·200·400턴 코일을 각각 감아. 100턴마다 멀티미터 저항 모드로 R_coil 측정해 표에 기록(이게 KVL 풀이의 입력값). 친구·동생에게 카운터 부탁하면 시간 절약. 권선 후 코일 양 끝 에나멜을 사포로 살짝 벗겨야 접촉 OK. 코일별 두께·길이 사진을 찍어 보고서에 비교 사진 1장으로.✓ 완성품: 권선수 4종 코일 + R_coil 4개 값 + 비교 사진 1장.
  3. 변수 36조합(4×3×3) 측정 데이터 수집⏱ 3~4h
    4 권선수 × 3 자석 × 3 높이 = 36 조합 × 10회 평균 = 360 측정. Google Sheets에 권선수 / 자석 / 높이 / V_max(10회 평균) / 표준편차 360행. 자석은 같은 손으로 같은 자세에서 떨어뜨리는 게 핵심(낙하 자세 변동이 가장 큰 노이즈). =AVERAGE·=STDEV로 자동 계산. 데이터 입력하면서 패턴 보이는 순간이 가장 재미있을 거야 — N과 V_max가 정말 비례하는지!✓ 완성품: 360행 측정 시트 1개 + 평균·표준편차 표.
  4. 이론 vs 실측 비교 + 오차 분해 보고서⏱ 2~3h
    이론값 ε = -N·dΦ/dt를 자석 자속 Φ = B·A로 근사 계산. 실측값과 비율(η = ε_실측/ε_이론)을 권선수별로 그래프로. 비율이 100%가 안 나오는 차이를 자기 누설(35%)·코일 저항 손실(25%)·낙하 자세 오차(40%)처럼 본인 추정으로 분해. 마지막 한 단락: "왜 N=400턴에서 효율이 다시 떨어지는가" — 코일 직경 증가로 자석에서 멀어진다는 본인 해석. 물리 교과샘께 5분 검토 받기.✓ 완성품: 3축 그래프 1장 + A4 인포그래픽 1매 + 보고서 5쪽.

🤖 3. 루빅큐브 분류기 v2 — 데이터셋 100장 + CNN 성능 재평가

난이도 ★☆☆ 3~4주(분산) 키워드 연결: 이미지 분류 CNN·데이터 설계
💚 왜 겸이에게? 2학년 인공지능 기초에서 본인이 직접 라벨링한 분류 모델의 가장 솔직한 반성("데이터가 부족했다")의 후속편. 같은 주제를 한 단계 더 깊게 가져가는 흐름이라 키워드 수직 연계 ②를 1·2학년 → 3학년까지 잇고, 실험 부담이 가장 적어 3학년 시기에 안전한 카드. 공학·AI 융합 진로 면접에서 "데이터를 직접 만들어본 경험"이 가장 강력한 답이 돼.

📚 알아두면 좋은 핵심 이론

  • 혼동행렬(Confusion Matrix): 예측 vs 실제를 4칸(TP·TN·FP·FN)으로 펼친 표. 정확도만으로 못 보는 클래스별 약점이 드러나.
  • F1 Score: 정밀도와 재현율의 조화평균. 두 클래스 데이터가 불균형할 때 정확도보다 신뢰할 수 있는 지표.
  • 데이터 증강(Data Augmentation): 회전·밝기·뒤집기로 같은 이미지를 변형해 학습 데이터를 인공적으로 늘리는 기법. 작은 데이터셋의 기본기.
  • CNN(합성곱 신경망): 이미지 분류의 표준 구조. 합성곱 → 풀링 → FC의 순서로 픽셀에서 점점 추상적인 특징을 추출해.
  • 과적합(Overfitting): 학습 데이터엔 잘 맞지만 새 데이터엔 못 맞추는 상태. 데이터 100장이 10장보다 강한 이유가 바로 이걸 줄여주기 때문.

A. 실험형 / 실천형

  • 2학년 모델 데이터를 10장 → 100장으로 확장(직접 라벨링)
  • 학습:검증 = 8:2 분할, 정확도·혼동행렬·F1 score 비교 (전·후)
  • 이미지 회전·밝기 증강 추가했을 때 성능 변화
  • 한계와 다음 단계(3D 인식·실시간 큐브 풀이 안내) 본인 언어로 정리

B. 문헌형

  • DBpia·RISS 이미지 분류 데이터 증강, CNN small dataset
  • 한국정보과학회·한국컴퓨터정보학회 학회지의 소규모 데이터 학습 사례
  • 한국지능정보사회진흥원(NIA) AI 허브 라벨링 가이드라인
  • 단행본: '밑바닥부터 시작하는 딥러닝 1' 6·7장, '핸즈온 머신러닝' 데이터 전처리

🚀 어떻게 시작하면 될까

  1. 큐브 사진 100장 직접 촬영 + 라벨링⏱ 3~4h(분산)
    스마트폰으로 6면 큐브를 다양한 각도·조명에서 100장. 각 이미지에 두 풀이 기법 중 효과적인 쪽을 본인이 직접 풀어보고 라벨링. 폴더 구조 data/method_A/img001.jpg·data/method_B/img001.jpg로 정리. 친구·동생 도와주면 50장은 1시간 안에. 라벨 일관성을 위해 같은 사람이 같은 기준으로 끝까지 — NIA AI 허브의 라벨링 가이드라인 1편 참고.✓ 완성품: 100장 폴더 + 라벨 시트 .csv 1개 + 라벨링 기준 메모 1쪽.
  2. Colab에서 CNN 학습 — 10장 vs 100장 비교⏱ 2~3h
    Google Colab(colab.research.google.com) 새 노트북:
    from tensorflow.keras.preprocessing.image import ImageDataGenerator
    from tensorflow.keras.models import Sequential
    from tensorflow.keras.layers import Conv2D, MaxPooling2D, Flatten, Dense
    모델은 Conv2D(32,3,3) → MaxPooling → Conv2D(64,3,3) → MaxPooling → Flatten → Dense(64) → Dense(2,'softmax') 같은 단순 구조로 시작. 두 번 학습 — (a) 2학년 데이터 10장만, (b) 새 100장. 각각 model.fit의 history를 그래프로 저장.✓ 완성품: 학습 곡선 그래프 2장(.png) + 모델 .h5 2개.
  3. 혼동행렬·F1 score로 성능 정량 비교⏱ 1~2h
    from sklearn.metrics import confusion_matrix, f1_score, classification_report
    두 모델의 검증 데이터에 대한 예측을 만들어 confusion_matrix와 F1을 출력. seaborn.heatmap으로 혼동행렬을 시각화. 결과 표 모델 / 정확도 / 정밀도 / 재현율 / F1 5개 컬럼 → 본인 한 줄 해석: "100장 모델은 정확도는 비슷해도 F1이 높아 두 클래스 모두 잘 잡는다" 같은 식. 과적합 신호도 학습-검증 정확도 갭으로 확인.✓ 완성품: 혼동행렬 히트맵 2장 + 성능 비교 표 1쪽.
  4. 데이터 증강 추가 + 한계 정리 보고서⏱ 2~3h
    ImageDataGenerator(rotation_range=30, brightness_range=[0.7,1.3], horizontal_flip=True)로 학습 데이터 증강 후 같은 모델 다시 학습. F1 score가 얼마나 올라가는지 비교. 마지막 보고서 한 단락: "왜 100장이 10장보다 강한가 — 과적합 감소 측면에서"를 본인 언어로. 다음 단계로 (a) 3D 회전 인식, (b) 실시간 큐브 풀이 안내, (c) 더 깊은 CNN 또는 전이학습(VGG16 fine-tune) 중 하나를 진로 면접용 멘트로 1단락 정리.✓ 완성품: 증강 전·후 F1 비교 표 + 한계·다음 단계 보고서 6쪽.
